## JWT identities

`orchestrator`, `amr-1-cognition`, `amr-2-cognition`, `arm-1-cognition`, `maintenance`.
Static HS256/RS256 tokens generated by `scripts/gen-jwts.py` into `gateway/jwt/`. Never
commit real secrets; these are demo-only keys, regenerated on setup.

## The five pillars (acceptance contract — PRD §2)

| Pillar | Demo proof | SLO |
|---|---|---|
| **Safety** | gated tools invisible & denied for non-maintenance; audit log w/ args+identity; e-stop in-process | 100% gated invisible/denied; 100% actions audited; e-stop ≤10ms, never on network |
| **Failover** | kill primary Ollama → fallback rung serves next request; kill cognition → robot safe-idles, fleet continues | failover on next request; SAFE_IDLE ≤500ms sim; missions complete with any single component down |
| **Speed** | live bench table direct vs gateway; local vs cloud RTT | gateway p99 overhead ≤10ms (non-inference); reflex 0 hops |
| **Repeatability** | agentevals scores two OTel traces, reports drift; CI gate on behavior | 10 identical CI runs vs mock-llm; one config artifact everywhere |
| **Predictability** | chaos prompts (incl. pallet-label injection) → 0 escapes; budget exhaustion → clean 429 | 0 escapes across ≥20 cases; envelope diffable in git |

## Operational gotcha: gateway DNS after a rebuild

agentgateway resolves backend addresses on start. If you `docker compose up
--build` a backend (world/robots/agents/mocks) it may get a NEW container IP,
and a long-running gateway will keep hitting the old one (500s / "connection
refused"). Fix: `make reset-gateway` (force-recreates just the gateway).
`make up` already starts the gateway last, and `demo.sh` preflights this.

## Rules for this repo

- 100% OSS default path. No cloud keys. `ENABLE_CLOUD_FALLBACK` gated, default off.
- Boring code: FastAPI, official `mcp` SDK, plain `openai` client. No agent frameworks.
- Cognition talks to tools ONLY through the gateway. Reflex tier NEVER touches the network.
- Don't guess gateway config syntax — check docs/agentgateway-v1.4-reference.md.
- OTel spans from M1 onward; every agent emits task/plan/tool-call spans.
- Multi-arch (arm64+amd64) images; CI runs on mock-llm only.
- Each milestone lands as its own commit with its verify target green first.
